# Macro token locations in the preprocessing specification

The line-splice compiler tests exposed an independent specification bug:
`expand` overwrote every argument token's line with the closing parenthesis's
line, and `substitute` then overwrote all result locations again. This made
`I(\n__LINE__)` and exposed function macros report the wrong source line.

`Spec/Pre/Expand.lean` now preserves argument token locations. Replacement-list
tokens and paste results, including placemarkers, take the macro-name token's
invocation line. Stringification and hide sets retain their existing rules.
Seven new guards check these distinctions under both ISO and tcc configs.
This corrects C11 source provenance; no Supported/Fits restriction changes.

The capped `CSemPre pre_spec` build passes, including every guard. Strict
comparison against the frozen line-repair cross compiler and cross GCC gives
**38/38 exact agreements**, including all seven previously differing cases.
The default corpus diagnostic gives **609 exact tcc agreements / 617 inputs**:
one known signed-character parameter difference, two UB examples and five
fixture errors remain separate. GCC has 605 exact agreements and five
differences, with the same seven UB/fixture classifications. No spelling or
error normalization was added. Raw tables are `line-spec-repaired.tsv` and
`line-spec-corpus.tsv`.

The focused inputs are the original `results/repro/tcc_line_splice.c`, the
36 cases generated by `scripts/gen_line_fixtures.py`, and
`c/tests/c11/line_varargs.c` from the line worker. The compiler used was that
worker's `build/cross/riscv64-tcc`, with exact source/build pins in
`results/pre/line-build.json`. Its compiler/model repair is a separate change.
The preprocessing spec driver was built from this repair. Static gate passes.
The exact internal-token observation and include-path repairs remain open.

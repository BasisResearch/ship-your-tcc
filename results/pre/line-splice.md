# Physical `__LINE__` provenance repair — 2026-10-27

Patch 0003 now retains the presumed line of a token's first physical
character before lexer lookahead. The file cursor still counts every
backslash/newline (including phase-1 trigraph backslashes) so later tokens,
`#line` and include resumption retain their physical positions.

The separate `tok_line` state is saved/restored with macro frames. Internal
`TOK_PPLINE` records carry it through captured arguments, cached expanded
arguments, substitution and rescanning; `__LINE__` reads that state.
Stringification ignores the records, whitespace remains outside them, and
`##` skips records while finding operands. Paste results, including
placemarkers, receive the invocation line; ordinary substituted arguments
retain their own token lines. `_Pragma` preserves the caller's provenance.
GNU variadic comma deletion walks complete tokens rather than comparing raw
words, so a line payload of 44 cannot be mistaken for punctuation.
The executable model independently mirrors these compiler operations.
Token constants were regenerated by `scripts/gen_model_tok.py`.

No CSem meaning, Supported/Fits condition, theorem, premise, elaboration
budget, vendor source or frozen sum cut was changed.

## Dead ends

The first `_Pragma` fixture was invalid at an initializer expression;
GCC rejected it. The corrected fixture places it at a declaration boundary.
The first capped request's Lean jobs completed, but the lead correctly
rejected its evidence because this generator correction changed a frozen
hash. Only a matching final request/result is accepted.

Capturing only a token-start line loses it when macro arguments are read.
Conversely, carrying the raw first paste operand's line gives 301 instead
of GCC's 300 for a macro invoked at line 300 with its operands on later
lines. Stream provenance plus invocation locations for paste covers both. A later
stream audit caught the variadic comma-deletion collision with line 44; the
compiler/model now use token-aware traversal, with a dedicated regression.

The initial model quota mistakenly included the preprocessing-only
`c/tests/pre/line.c`, which has no main and yields a matching linker
refusal. It is excluded from the final successful-arena quota. One spec
run also overlapped a runtime-triggered cross rebuild and found the
compiler temporarily absent; the sequential rerun supplies the retained
strict results. These failures are recorded in `tasks/DEAD-ENDS.md`.

The first evidence-validator draft also incorrectly expected a `SUCCESS`
chatter line in Sail stdout. Trace mode sends diagnostics to stderr and this
program's correct stdout is empty. The verifier now checks exact empty
console, verified successful lead exit and all three expected trace cuts.

The local systemd user bus is denied. Builds use the lead service under
the shared lock and 12 GB cap. The lead note arrived after the initial
request and was read before the final request. Git staging also failed at the read-only worktree `index.lock`; a frozen
manifest in `build/worker-commit.request` supplies the authorized lead commit. No uncapped fallback,
network operation, external message, subagent, push or main merge was used.

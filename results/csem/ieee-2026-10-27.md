# Pure IEEE recovery and CSem integration — 2026-10-27

The native floating seam is replaced by pure configured binary32/64/128
values. This is ready for review of the semantics change; it is not closure
of the whole-C theorem or of the target library connections. Fresh Sail
comparisons expose literal-accuracy, long-double printf and sqrtl differences;
CSem retains full precision rather than adopting the target's lossy behavior.

## Changes

- `CerbMem.FloatingValue` and the Lem Float target representation use `FVal`,
  carrying a format and exact interchange bits. No native Float executes in
  the semantic closure.
- The frontend selects the configured format from the separate Ail literal
  suffix before rounding. Typed integer conversions round once directly to
  their destination. Explicit floating casts, mixed arithmetic, conditional
  arms, function parameters and float default argument promotions retain the
  destination format. Long double stays long double in variadic calls.
- Five typed Core constructors express value/loaded conversions and unary
  negation. Negation flips the sign bit, including zero and NaNs. Non-finite
  conversion to an integer reaches UB017; existing C helpers retain target
  integer range checks and the special Boolean conversion.
- Loads/stores use 4/8/16-byte configured representations. Equal-format copies
  preserve NaN signs and payloads. Reconstruction reference tests preserve
  their traversal/diagnostic contracts while updating the shared floating leaf.
- Floating printf supports f/F/e/E/g/G/a/A and L, operating on exact values,
  with flags, width and precision. Signed NaNs print instead of being refused.
  The inherited asterisk formatting TODOs, N3 rounded libc Core dump,
  partial parsers and dynamic fenv/library coverage remain separate gaps.
- The manifest and generator copy target install the handwritten module;
  all generated sources come from the generators. The datatype-derived
  quotation visitor now has 643 constructors; it quotes exact floating bits.
  The changed reader reaches two existing measured proofs and generated
  fuel-parametricity pins; no budget was increased.
- Lake/gates include IEEE tests and a native-floating regression check in
  both kernel and runtime dependency closures. The axiom audit includes the
  recovered arithmetic/byte bridges and open connection statements.

## Changed observations and remaining connections

`focused-comparison.json` stores the exact expected/observed bytes and exit
codes. Four programs agree: formats, bytes, NaN byte copies, and NaN format
conversions. The two literal probes share one cause; printf is a separate
library discrepancy. The separate UB017 probe is not a defined Sail comparison.

1. **Literal accuracy.** The minimized `literal-rounding.c` prints
   `3f800000 3f800000` on tcc/Sail versus CSem `3f800001 3f800000`.
   The first decimal is just above the binary32 halfway point. TinyCC calls
   the image's `strtof` in its literal path; the observation is consistent
   with double rounding. The chosen pure model rounds directly to binary32.
   This is a target/model accuracy discrepancy, not a claimed proof of C11
   nonconformance. It needs repair or explicit standards/configuration
   reconciliation. Supported is not narrowed.
2. **Long-double printf.** Both tcc/Sail and independent xgcc/Sail observations
   lose binary128 precision/range in newlib's formatting path. The focused
   continuation prints `1.000...000`, `0x1p+0` and `inf`, while CSem prints the
   low binary128 precision digits, `0x1.0000000000000000000000000001p+0`
   and `1e+4000`. The binary64 formatting line agrees. The C function returning
   zero is not output agreement. CSem is not narrowed to binary64.
3. **sqrtl.** Nine finite results differ in the full 32-input Sail vector run.
   Same-input host sqrtq and the pure model agree; all nine input/target/host
   bit triples are in `sqrtl-residuals.json`. No rows are removed from the
   failed Sail comparison or classified as passing library refinement.
4. **Old seam failures.** The saved old CSem binary crashes when serializing
   the new float-format/rounding probes, and returns 1 for the NaN-byte case.
   The new defined-zero results are repairs, not unexplained baseline changes.
   Non-finite integer conversion changes from a native crash to UB017.

Named typed obligations in PHASES.md remain open:
`CerbIEEE.FormatConversionValue_Statement` (NaN extension field proof),
`Tcc.CSem.IEEE.RV64LibgccIEEE_Statement` (actual image-pinned helper relations),
`Tcc.CSem.IEEE.NewlibIEEE_Statement` (sqrt/floating printf), and
`Tcc.CSem.IEEE.TccLiteralIEEE_Statement` (target literal path).
The abstract call relations are not asserted to describe an image. No
whole-C, all-library or end-to-end closure is claimed.

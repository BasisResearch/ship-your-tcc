builds and passes the integrated gates on approved Lean 4.34, with the fork's
readers, image FS and theorem shape preserved. However, current upstream
newly refuses a valid supported C11 program, `union-second.c`. Both its

case before changing the active main pin; do not narrow `Supported` or add

## Semantic changes and concrete adoption gap

Minimal complete programs and raw captures are in `probes/`,
`upstream-probes/` and `lean-probes/`; `CSEM-UPSTREAM.md` tracks dispositions.

| reproducer | old OCaml | current OCaml / repinned Lean | ruling |
|---|---|---|---|
| `bool-float.c`: `(_Bool)0.5` | returns 0 | both return **1** | upstream C11 Boolean-conversion repair |
| `bool-pointer-call.c` | returns 1 | both return 1 | default calling convention preserved |
| `union-second.c`: two `int` union members, initialize `.b = 7`, return `u.b` | returns **7** | OCaml exit 125, Lean exit 134, refusal | **valid C11 regression; adoption concern** |
| `memcpy-overlap.c` | defined answer 0 | both refuse | avoids an old defined answer on C UB, but a refusal is not a UB_MATCH result |
| `gnu-cleanup.c`, `knr.c` | parser rejection | same current-upstream parser rejection | approved whole-C compatibility gaps remain |
| `link-header.c` | undeclared `link` | same pristine-runtime failure | local image-runtime correction remains necessary |

Upstream's union refusal protects its acknowledged general initializer bug,
but its guard rejects the simple valid same-type case too. It is not a
correct implementation of designated union initialization. That is a
concrete semantic gap after the infrastructure and 4.34-port questions have
been resolved. Retain the active pin until a corrected union implementation
or an explicitly reviewed adoption decision addresses this evidence. The
approved theorem, `Supported`, and resource bounds were not changed.

## Dead ends and limits

* The earlier worker's DNS/bus/Git limitations are historical, not the
  outcome of this continuation. Lead-fetched snapshots, capped service builds
  and the isolated generator build all worked.
* First candidate build failed only in two newly added test adapters because
  a local instance preceded later imports. Those unnecessary adapters were
  removed; the semantics/proof groups had compiled. Keep the successful 05
  build as validation, not the failed 04 build.
* Directly retaining upstream's generic stop printer increases the theorem
  cone's partial population. The total encoding adapter is required to avoid
  that regression; passing an axiom census alone would not establish purity.
* A stale `build/csem-libc.args` produced a real runtime-location refusal.
  Content-addressed preparation fixed the cache; the guard was not weakened.
* Local execution of capped capture tests failed at the sandbox bus. The
  final lead-run 25-test suite passed; the local failure log is retained only
  as an unsuccessful attempt.
* Full standalone upstream lanes outside the original root-integrated fork
  gate, including quotation round-trip/plugin tests, are not claimed passed.
  Their scope is listed in `csem/PORT-4.34.md`; quotation local controls are
  included in the 21 tested executables.

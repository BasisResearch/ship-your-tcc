## Actual control path and retained fields

`tcc_predefs` records the byte offset at the branch that appends the implicit
`#include <tccdefs.h>`. `preprocess_start` binds this designation to the actual
new command-line opening ID and its complete generated bytes. `parse_include`
records `Ghost.CompilerEvent` only when that parent ID and exact directive
occurrence actually open a header. The event retains the root/header IDs,
full predefine/header bytes, resolved identities and actual include edge.
Filename, presumed label, source order and builtin spelling do not designate
this event. No spec preprocessing, returned Cabs or exported witness constructs
model data.

`CompilerEvent.authority` checks full bytes against the fixed cfgTcc/image
pins and retains the designated edge in `Phase7.CompilerOpening`. A same-path
content change yields no authority. User re-inclusion has its own opening and
edge, so even identical header bytes receive no injected authority. The
comparison checks requested override bytes against actual retained openings.
The existing independent header checks also reproduce the actual stripped
image header from its stripper and generated Spec.ImageFS; the pristine
unstripped source header is a separate byte pin.

`PpMacro.ghostTokenStart` maps the model-owned origin's **identitySite** through
`Phase7.identify`, with named `sourceIdentity` fields on both endpoints.
Diagnostic positions still follow **Origin.site**. Ordinary runtime membership
comes from the separately supplied resolved-file policy. Direct tokens, header
macros, argument identity and latest redefinitions retain their independent
identities. The nested-library and same-text-redefinition controls check these
fields directly, including library identity under an ordinary presumed label.

The real generated predefine buffer has model-owned byte coordinates; paste
and pragma buffers remain synthetic. Chained `##` now retains the accumulated
left ghost derivation when TOK_PLCHLDR denotes a nonempty paste accumulator.
Compiler token words and generated code are unchanged.

`Ghost.openingFiles` names the predefine/header roles by actual control IDs.
It expresses the spec's predefine/header-first processing schedule while
retaining every other physical model opening in order, including main, empty
files and repeated user header openings. The unprojected actual opening IDs
and order remain in every capture. No spec source-name set filters model data.
